# พอร์ตงานค้นหาโครงการและคลังเอกสารประกวดราคา

## สิ่งที่ระบบเดิมทำ

1. ค้นคำในชื่อโครงการผ่านหน้า Process3 สาธารณะ, แปลงตาราง Windows-874
   เป็นรายการโครงการ และกรองประกาศยกเลิก/เก่ากว่าช่วงวันที่เลือก.
2. หน้ารายการแสดงเลขโครงการ, หน่วยงาน, วงเงิน, สถานะ, วันประกาศ และลิงก์
   อ้างอิงไปหน้าค้นหา Process5. มี CSV และ cache ชั่วคราว 30 นาที.
3. งานเก็บเอกสารตามคำค้นดาวน์โหลด ZIP ของโครงการ, แตก PDF, อ่านวันเสนอราคา
   และค่าใช้จ่ายจาก PDF ด้วย `pdftotext`, แล้วเก็บ metadata และไฟล์ในคลัง.

## ขอบเขตที่พอร์ตแล้ว

- `budget_addons/budget/tenders.py` แยก parser และ search service ออกจาก UI;
  รับเฉพาะคำค้นที่ผู้ใช้ระบุ, จำกัด 6 หน้า/คำ, เว้น 1 วินาที, ตัดรายการซ้ำ.
- `GET /api/tenders` อยู่หลังการยืนยันตัวตนเดิม, จำกัด 8 คำค้น/500 ตัวอักษร,
  `days` 7–365 วัน. ตอบ `complete=false` พร้อม warning เมื่อหน้าไม่ครบหรือ
  ไม่สามารถยืนยันว่าไม่มีผลลัพธ์จริง.
- ไม่มีการเขียนลง source mounts และไม่มีการเปลี่ยนงาน Web Watch ปัจจุบัน.
  นี่เป็นการค้นหาแบบผู้ใช้สั่ง ไม่ใช่การลงทะเบียน source เพื่อเฝ้าดูต่อเนื่อง.

## สิ่งที่ยังต้องออกแบบก่อนเปิดคลังเอกสาร

- เลือก storage เขียนได้สำหรับ ZIP/PDF **แยกจาก** `data/` และ `/docs`;
  metadata และสถานะงานควรอยู่ใน pstack PostgreSQL. ห้ามนำ path/ไฟล์จริง
  หรือเนื้อหาที่อาจมีข้อมูลส่วนบุคคลเข้า repo สาธารณะหรือโต๊ะกลาง.
- กำหนดสิทธิ์เข้าถึง, retention, quota, malware/ZIP-slip และขนาดไฟล์,
  รวมทั้งสิทธิ์/เงื่อนไขของ API เอกสารก่อนทำ downloader.
- แยก worker สำหรับ harvest, retry และ audit; ใช้คำค้นที่มนุษย์ลงทะเบียน
  ไม่ฝังคำค้นของงานจริงในโค้ด. ปรับตัวแยกวันเสนอราคา/ค่าใช้จ่ายให้มี
  provenance ของหน้า PDF และสถานะ `unknown` เมื่อ parse ไม่แน่ใจ.
- ทดสอบ parity กับตัวอย่างที่เจ้าของงานเลือกโดยไม่คัดลอกข้อมูลจริงเข้า tests,
  แล้วรัน candidate แยกจากระบบเดิมก่อน cutover. ยังไม่มีการอนุมัติ cutover.
